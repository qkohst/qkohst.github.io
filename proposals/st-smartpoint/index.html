Summary

  1. 01

    A checkout system that runs in the browser, usable from any till computer without installing extra software.

  2. 02

    The checkout screen is built for speed: the whole flow can be driven from the keyboard without touching a mouse.

  3. 03

    One product can be sold in different units — a pack or a carton — with stock still counted correctly.

  4. 04

    Two routes available: buy a ready-to-use licence, or have it built around your own shop's workflow.

The problem it solves

  • Sales are still written in a book or a spreadsheet, so the daily figure is only known after closing.
  • Recorded stock never matches the shelf, and the gap only surfaces at stocktake.
  • Products sold both loose and by the box are hard to count because the units differ.
  • There is no way to confirm that a cashier's takings match the sales that actually happened.
  • Stock running low goes unnoticed until a customer asks for it.
  • Off-the-shelf POS software charges a monthly subscription that never stops.

Proposal · St SmartPoint 04

The proposed solution

Every transaction is recorded as it happens, so daily, per-product, and per-cashier sales reports are available at any moment without waiting for a tally.

Stock decreases automatically on a sale and increases automatically when a supplier purchase is recorded, with unit conversion handled by the system rather than by the cashier.

Being web-based, one installation serves several till computers on the shop network at once, and the owner can read the reports from anywhere.

Who uses it

  • AdminMaster data, supplier purchasing, reports, and application settings.
  • CashierServing sales, printing receipts, and reviewing their own transaction history.

Questions and answers

What if the developer stops working or cannot be reached?
The application keeps running because it is installed on your own server, not on a service I operate. A copy of the database and instructions for backing it up are handed over at handover, so another developer can take over if needed.
Why is the source code not included?
That is precisely why the licence costs far less than building from scratch. If you do need the source code, there is the bespoke route, or buying the source code under a separate agreement.
Can our existing data be moved in?
Yes, as long as it is in Excel or can be exported to Excel. Loading the initial data is included in the licence price.
Is there a limit on the number of users?
No. The licence covers one institution with no cap on accounts or on the number of computers using it.
What if we need a menu or report that does not exist yet?
It can be added as additional work. The estimated hours and cost are stated and agreed first — never built quietly and invoiced afterwards.
Do we need an internet connection?
Not necessarily. Installed on a local server, the application runs over the network inside the building. Internet is only needed if you want to open it from outside.
Can we try it before buying?
Yes. I will show you the application running with sample data, over an online meeting or a visit, before you decide.
