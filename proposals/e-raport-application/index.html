Proposal · E-Raport Application 03

Summary

  1. 01

    A report-card application that follows your own subject list, including the local-content subjects the government-issued tool cannot hold.

  2. 02

    Supports two curricula side by side, KTSP 2006 and K13, so a school mid-transition does not need two separate systems.

  3. 03

    Four user roles — Admin, Subject Teacher, Homeroom Teacher, and Student — each seeing only their own work.

  4. 04

    Two routes available: buy a ready-to-use licence, or have it built around your school's own assessment rules.

The problem it solves

  • The government-issued report tool has no room for local-content subjects, so those marks are still worked out by hand outside the system.
  • Marks arrive as spreadsheets in a different shape from every teacher, then have to be merged again by one person.
  • Homeroom teachers retype an achievement description for every student, even though they all derive from the same competencies.
  • As report day approaches, there is no quick way to see whose marks are still missing.
  • Predicates and pass thresholds are worked out by hand, so a small discrepancy is hard to trace when a correction comes in.
  • Report cards and student ID cards are rebuilt from scratch every term, from files that already existed last year.

Proposal · E-Raport Application 04

The proposed solution

The school registers its own subjects, local content included, each with its pass threshold and predicate bands. The system takes that list as given, so no subject is left to be calculated outside the application.

Teachers enter marks directly against the basic competencies they teach, and each student's achievement description is assembled from those same competencies. The homeroom teacher reviews rather than retypes.

The admin sees a completeness board showing each teacher's planning and assessment status per subject, so anything lagging surfaces well before report day.

Who uses it

  • AdminMaster data, teaching assignments, pass thresholds, predicate bands, and grading progress monitoring.
  • Subject TeacherAssessment plans and entry of knowledge, skill, attitude, and extracurricular marks.
  • Homeroom TeacherAttendance, notes, review of their class's marks, and printing report cards.
  • StudentViewing their own marks and report results.

Questions and answers

What if the developer stops working or cannot be reached?
The application keeps running because it is installed on your own server, not on a service I operate. A copy of the database and instructions for backing it up are handed over at handover, so another developer can take over if needed.
Why is the source code not included?
That is precisely why the licence costs far less than building from scratch. If you do need the source code, there is the bespoke route, or buying the source code under a separate agreement.
Can our existing data be moved in?
Yes, as long as it is in Excel or can be exported to Excel. Loading the initial data is included in the licence price.
Is there a limit on the number of users?
No. The licence covers one institution with no cap on accounts or on the number of computers using it.
What if we need a menu or report that does not exist yet?
It can be added as additional work. The estimated hours and cost are stated and agreed first — never built quietly and invoiced afterwards.
Do we need an internet connection?
Not necessarily. Installed on a local server, the application runs over the network inside the building. Internet is only needed if you want to open it from outside.
Can we try it before buying?
Yes. I will show you the application running with sample data, over an online meeting or a visit, before you decide.
